# 任务拆解（Task Breakdown）

当一个需求模糊、复杂或跨领域时，先用本技能把它变成可执行的计划。

## 步骤

1. **澄清目标**：明确"最终交付物是什么、给谁用、验收标准是什么"。
2. **拆解问题链**：把需求拆成若干独立子问题，标注依赖关系（哪些必须先行）。
3. **每个子问题产出可执行步骤**：每一步都要有"做什么 + 产出什么 + 如何验证"。
4. **识别风险与前置条件**：哪些步骤需要外部信息/工具/人，卡住时怎么办。
5. **输出结构化清单**：用编号步骤 + 依赖箭头（A → B），并给出预计工作量（S/M/L）。

## 输出模板

```
## 目标
- 交付物：...
- 验收标准：...

## 问题链
1. [前置] 收集背景信息
2. [核心] 设计/实现主体
3. [依赖 2] 验证与收尾

## 执行步骤
- [ ] 1. ... （产出：...，验证：...）
- [ ] 2. ...

## 风险
- ...
```
